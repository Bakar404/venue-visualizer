# Decisions log

## 2026-11-21: No paid image or LLM APIs; bring your own subscription
Users bring only subscription-billed coding agents (Claude Code, Codex, GitHub Copilot, Kimi Code).
Image generation goes through the official CLIs' built-in image tools (Copilot CLI image tool, Codex
`$imagegen`), local diffusion (mflux), or a non-AI 3D render. The app is local-first and never hosted for others,
because subscriptions are personal.

## 2026-11-21: Only official CLIs, never token reuse
Projects like codex-imagegen-cli and CLIProxyAPI read CLI auth files and call vendor backends directly.
That is fragile and likely against the vendors' terms. We spawn the official binaries only.

## 2026-11-21: Copilot CLI image tool works headlessly (verified)
In a probe with Copilot CLI 1.0.115, `copilot -p` exposed `image_generation(prompt, input_images, size, quality)`.
It generated an empty ballroom from text (1536x1024, about 29 s), then edited it with decor while keeping walls,
windows, chandeliers and the camera angle (about 27 s). It drew 5 tables instead of the requested 6, so counts are
not reliable. Mitigations: QA counting, and the scene3d engine for exact layouts.

## 2026-11-21: Fixed pipeline with a chat front end, not an autonomous agent
Both second opinions (Gemini 4 Argon, GPT 6.1 Sol via Copilot) agreed: the LLM proposes a typed merge patch,
deterministic code enforces venue rules, and renders only happen on an explicit click. This keeps quota spend
predictable and makes form edits and chat edits identical.

## 2026-11-21: Always render from the base photo plus the full spec
Never chain edits on previous renders. This avoids cumulative drift. Variations are new Looks with a parent pointer.

## 2026-11-21: SQLite job table plus a separate worker process; no Redis
GPT suggested RQ+Redis and Gemini suggested an in-process asyncio worker. We chose the middle path: a durable SQLite
table and a separate worker process. Jobs survive API restarts and there is no extra infrastructure.

## 2026-11-21: Structure verification with edge SSIM on the upper frame
Cheap, offline (OpenCV + scikit-image), and engine-agnostic. The threshold will be calibrated on sample runs.
SAM 2 / Depth Anything masks are deferred until benchmarks show they are needed.

## 2026-11-21: The JSON Schema is the source of truth
`packages/schema/*.schema.json` generates the TS types (json-schema-to-typescript) and the Pydantic models
(datamodel-code-generator). Both are checked in and regenerated by `make schema`.

## 2026-11-21: The personal spec stays out of the public repo
The original spec has personal event details and lives in `private/` (gitignored).

## 2026-11-21: Venue finder: research real venues on the web (supersedes a spec non-goal)
The original spec excluded taking venue photos from the web. The user now wants the agent to find real venues
(e.g. "Grand Hotel, Riverside Ballroom"). Compromise: the agent researches publicly posted info with sources; nothing is
used until the user confirms it. Web photos default to *reference only* (used to ground a generated base view), and are
imported as editable base photos only when the user confirms they have the right to. Credits are kept. Published venue
policies are suggestions until the user accepts them. Research runs through the user's own CLI web tools, not a scraper.

## 2026-11-21: Output is always photoreal; 3D is a hidden layout guide
The user wants results that look like real photographs, not 3D or illustrated scenes. So:
- The user-facing engines are the photoreal ones only: copilot, codex and mflux. `scene3d` is never shown as an output and is
  removed from the engine picker.
- `scene3d` becomes an internal **layout guide**. When exact counts matter (e.g. "12 tables"), it renders a plain top-down or
  eye-level layout image of the table positions. That image is passed to the photoreal engine as an extra reference ("place tables
  where this guide shows"), together with the real photo. The guide image itself is never shown as a result.
- The `mock` engine is for tests and `NEXT_PUBLIC_VV_MOCK` demos only. It is hidden from the picker unless `VV_DEV=1`.
- Demo and mock-mode imagery uses real photoreal renders (generated with Copilot's image tool, credited in
  `apps/web/public/samples/photoreal/CREDITS.md`), not SVG drawings.
- Prompts always ask for "a real photograph by a professional event photographer, 24mm, eye level, realistic materials, no CGI look".

## 2026-11-21: Video tours become base photos (not 3D)
A walkthrough video is turned into a curated set of sharp, diverse keyframes (ffmpeg + OpenCV). A vision-capable brain
labels and clusters them by space and drafts a VenueSpec per space. This keeps the output photoreal and reuses the photo
pipeline. Gaussian-splat reconstruction stays a later option. Web photos found by the venue finder may be used as base
photos after a one-time personal-use confirmation; this supersedes the earlier "reference only" default.

## 2026-11-21: Subprocesses never receive API credentials
Every CLI is spawned with `*_API_KEY`, `ANTHROPIC_AUTH_TOKEN` and similar variables removed from its environment. Some CLIs
(Claude Code, Codex) silently switch to per-token API billing when such a variable is present. Stripping them keeps
every call on the user's subscription login. Codex additionally runs with a minimal allow-listed environment.

## 2026-11-21: Local API hardening
The API only answers to localhost hosts (DNS-rebinding guard). It rejects cross-origin writes and requires JSON or multipart
bodies on writes, so a random website can't trigger research or render jobs that spend the user's quota.

## 2026-11-21: The structure check aligns before comparing (calibrated)
Copilot returns 3:2 images, while most phone and venue photos are 4:3. Resizing one onto the other made intact rooms
score as "altered" (0.32–0.53). The check now aligns the render to the photo with SIFT + RANSAC (similarity transform; scale
0.75–1.33, rotation ≤ 5°, sideways shift ≤ 6%, vertical shift ≤ 15%), then compares contrast-normalized edges
(edge F1, 3 px tolerance) over the top 40% of the frame. Calibration on 9 good and 6 bad real pairs: good renders scored 0.80–0.96,
and every wrong-room, other-angle or flipped pair failed alignment and is capped at 0.35. Threshold: 0.70.

## 2026-11-21: Structure check v2 (after review)
A GPT-6.2 Sol review broke v1. Some real photos skipped alignment and fell back to an uncapped grayscale comparison,
so different rooms and a blank render could pass. A missing chandelier hid behind an intact ceiling, and shifts were
measured from the corner, not the centre. v2:
- Alignment is gated on SIFT keypoints, not edge density. If the photo has structure and the render doesn't align
  (other room/angle, flipped, blank, heavy zoom or one-sided crop), it is capped at 0.35.
- The render's centre must map within 8% (x) / 12% (y) of the photo's centre. Inliers must cover ≥ 25% of a 4×4 grid.
  The render must cover ≥ 60% of the protected region.
- Score = min(edge F1, 10th-percentile per-tile recall + 0.25). Any covered architecture tile with recall < 0.20
  forces the score under the threshold.
- Photos with too little structure are "unverifiable" (0.50, below threshold) instead of passing by default.
- Decoding is bounded (≤ 4096 px, fitted to ≤ 1024 for analysis, aspect ≤ 4:1). Alpha is flattened onto grey and
  16-bit input is scaled.
Calibration (real renders plus attacks): every good render passes (0.78–0.96, including three Spring-Mill-style 4:3 → 3:2
renders). Every attack fails: other room, other angle, flipped, blank, chandeliers removed, windows removed,
one-sided crop, 1.25× zoom, transparent top. Of 66 pairs of video frames, 0 cross-room pairs pass.
Known conservative miss: a day photo re-rendered as a night scene (dark windows, blue uplighting, wider framing)
fails alignment and shows the "may have changed" warning even though the architecture is intact.
